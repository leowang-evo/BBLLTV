# 143：首页返回与索引首屏

## 首页返回

旧版根页面直接开启退出计时，未消费首页内容区的返回。现在 HomeFragment 实现 BackHandler：内容区返回先聚焦当前顶部标签并将内容对齐第 0 项，不重新请求或更换数据；已经聚焦该标签时，由 Activity 保留原有再次返回退出流程。顺序为：内容区返回 → 顶部标签；再返回 → 退出提示；提示期间再返回 → 退出。切换主导航、打开或返回子页以及被页面消费的返回会清除旧退出计时。

回到顶部同时取消待执行的列表焦点请求、清除旧卡片记忆。停留顶部导航时，迟到的增量更新保持首行；重新进入内容区后恢复正常锚点行为，避免把回顶部延迟到未来分页。

## 索引首屏

空列表默认带加载更多行，而首次网络请求被 post 到后续执行。空列表的首次布局可能先触发滚动监听，把页码从 1 加到 2，于是首次请求变成第二页，首批数据被当成追加，跳过原本的回顶部流程。诊断中实际观察到列表已自动追加到 73 项、首个可见位置为 36。旧代码也没有明确首次焦点，进一步放大了初始位置的不确定性。

现在在绑定时就标记首批加载中，空列表不显示加载更多行，分页监听忽略空数据，确保先完成第一页，再允许后续分页。

索引载入时先在返回图标保留焦点，首屏未建立时阻止海报和空列表容器自动接收坐标焦点。首批结果对齐第 0 项，若用户仍停在入口焦点则聚焦第一张海报；用户已转向筛选时保留筛选操作。追加分页不重置滚动，从详情返回仍恢复原海报。新筛选的首批结果回到顶部，请求代次和捕获页码防止旧筛选或旧分页覆盖新查询。

## 验证

HomeNavigationProbe 使用真实四个首页栏目、深度浏览和实体返回键，检查首次返回不触发退出、当前标签焦点、首行对齐、再次浏览不会恢复下方旧焦点、旧退出计时失效及顶部标签的退出确认。通过真实栏目“更多”进入番剧和热门电影索引，检查首行、第一张海报完整可见、详情返回及更换排序。

旧版观察模式只记录失败。测试要等待 ViewPager 的目标栏目确实可见；单个外层栏目可能包含多行海报，滚动深度须同时检查适配器位置和像素偏移，不能只看外层首项位置是否大于 0。

沿用同签名非调试 benchmark 构建与账号数据。首页、刷新、播放器及上版修复的搜索、动态、直播入口分别回归；本版结果和实测截图见 dist 的验证报告。独立源码构建、API21兼容、稳定资源 ID 及 APK 非签名条目一致性另行核对，未把旧版测试次数计作本版通过。
